# 웹 서비스 개선 계획

## 개발 범위

2026년 11월 6일에 정한 후속 개발 방향이다. 얼굴을 5개 부위로 나누는 기능은 제외하고,
사진별 탐지 결과와 시간에 따른 변화를 확인하는 서비스에 집중한다. 얼굴 부위로 장기 상태나
질환의 원인을 추정하는 기능도 포함하지 않는다. 기존 실험 문서는 당시의 계획과 결과로 보존한다.

첫 웹앱의 구조와 실행 방법은 [사진 분석 웹앱 구현 계획](web-analysis-mvp.md)에 둔다.
실제 기능과 저장 항목은 `web/`과 `backend/src/acne_care/`의 코드 및 테스트를 기준으로 확인한다.
이 문서는 완료 여부를 갱신하는 작업 목록으로 사용하지 않는다. 코드와 계획의 일치 여부를
자동 검사하는 장치는 없으므로 후속 기능을 개발할 때 해당 범위와 성공 기준을 다시 확인한다.

## 과거 기록 비교

먼저 과거 기록 하나와 현재 기록 하나를 선택해 사진과 탐지 개수를 나란히 확인하도록 한다.
촬영일 간격, 개수의 증감과 촬영 조건에 관한 안내를 함께 표시한다. 이후 여러 기록의
탐지 개수를 날짜순 그래프로 보여 주는 기능으로 확장한다.

모델, 가중치, confidence threshold와 입력 크기가 다른 기록은 같은 조건의 비교로 취급하지
않는다. 촬영 각도나 조명, 보이는 피부 면적이 달라도 개수가 달라질 수 있으므로 증감을
곧바로 피부의 호전이나 악화로 판정하지 않는다. 같은 날짜의 여러 기록도 구분해서 선택할 수
있어야 한다. 비교 계산과 모델 설정 차이에 관한 안내는 테스트로 검증한다.

## 분석 리포트

단일 분석과 과거 기록 비교를 한 화면에서 읽을 수 있는 리포트를 제공한다. 촬영일,
결과 사진, 탐지 개수, 비교 대상과 개수 변화, 분석 조건 및 해석의 한계를 포함한다.
리포트의 수치는 저장된 분석 결과에서 계산하고 별도 사본을 손으로 관리하지 않는다.
처음에는 화면과 인쇄 기능으로 제공하고 PDF 저장은 필요에 따라 확장한다.

생활 습관이나 식습관 안내를 넣는다면 출처가 있는 일반 정보로 제공한다. 여드름 위치만으로
원인이나 장기 이상을 단정하거나 특정 음식의 치료 효과를 보장하지 않는다. 구체적인 안내
문구와 출처는 해당 기능을 구현할 때 검토한다.

## 휴대폰 접속과 촬영

화면 크기 대응과 실제 휴대폰 접속을 구분해서 검증한다. 휴대폰 접속 환경을 정할 때
HTTPS, 접근 권한과 사진 저장 위치를 함께 설계한다. 로컬 전용 서버의 주소만 외부에
공개하는 방식으로 확장하지 않는다.

사진 업로드를 유지하면서 직접 촬영 기능을 추가한다. 카메라 권한을 거부하거나 카메라를
지원하지 않는 환경에서도 사진 업로드를 사용할 수 있어야 한다. 촬영 후에는 미리보기와
재촬영을 제공한다. 촬영일의 기본값은 기존 화면의 오늘 날짜 설정을 재사용한다.
실제 휴대폰에서 권한 허용과 거부, 세로·가로 사진의 방향을 확인한다.

## 사진 가림과 보관

스티커나 가림 처리는 리포트 표시 및 내보내기부터 적용한다. 분석에 사용한 사진과
가린 이미지를 구분하고 가림 처리로 기존 탐지 결과가 바뀌지 않도록 한다. 분석 전에
사진을 가리는 기능이 필요하다면 가린 영역의 탐지 제한을 별도로 설계한다.

사진과 분석 기록의 삭제, 원본 보관 여부, 내보내기에 포함할 정보의 선택도 함께 준비한다.
삭제 시에는 DB와 관련 사진을 모두 처리하고 다른 기록에 영향을 주지 않는지 확인한다.
가린 이미지를 저장하거나 공유할 때 원본이 함께 포함되지 않는지 검증한다.

## 화면과 촬영 안내

업로드, 결과, 기록 조회와 리포트 사이의 이동을 다듬고 휴대폰에서 버튼 크기와 글자,
사진 확대, 처리 중 표시와 오류 복구를 확인한다. 촬영 안내에는 조명, 각도, 거리와
피부 보정 필터에 관한 내용을 유지한다. 흐림이나 밝기를 자동 검사하는 기능은
실제 촬영 사례로 기준을 정한 뒤 추가한다.

## 구현 순서

과거 기록 비교와 변화 그래프를 먼저 구현하고 이를 바탕으로 리포트를 만든다.
그다음 휴대폰 접속 환경과 직접 촬영을 준비하며 사진 가림과 보관 설정을 추가한다.
화면 개선은 각 기능을 연결할 때 함께 검증한다. 학교 GPU에서 진행할 모델 학습 실험은
웹 서비스 개발과 분리해서 이어간다.
